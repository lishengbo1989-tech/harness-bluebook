案例集 → 生态案例: 人机协同规划

ECOSYSTEM CASE · PLANNING

人机协同规划:dsh-plans

PLANNINGGOALSHITL

先计划、后执行:变更请求沉淀为可追踪的 Markdown 计划,人在每个关键节点把关。

#场景与目标

大改动直接丢给 agent,容易跑着跑着就偏。dsh-plans 是 Human-in-the-loop 规划预设:先把仓库变更请求变成 ./dsh-plans/ 下可追踪的 Markdown 计划,再精修、再执行,每一步都有人的显式确认。给希望「人批计划、机器执行」的开发者。

#用到的能力

  • 计划即文件:变更请求沉淀为 ./dsh-plans/ 下的 Markdown 计划,可追踪、可评审。
  • 评审子代理:reviewer / criticizer 子代理多轮精修计划,评审子代理只读。
  • 持久目标:显式交接后交给持久 DSH goal 驱动执行,直到计划的 Verifier Checklist 全部通过。
  • 技能预设:内置 create-a-small-plan / create-a-plan / create-a-big-plan / diagnose-before-plan / reference-before-plan 五个技能。

#怎么做到的

先诊断再计划:reference-before-plan 先带参考上下文,diagnose-before-plan 先摸清问题;交互上每次只问一个问题、推荐项在前,减少人机来回;执行采用 ponytail 简化纪律与 MVP 最小测试集,验证清单不过就不算完成。

#实际效果

计划与执行分离,人在规划与交接节点把关;评审轮次精修加 Verifier Checklist 兜底,明显减少「干到一半发现方向错了」的返工。

#出处与上手

仓库:github.com/Optim-Agent/dsh-plans。安装命令:

git clone https://github.com/Optim-Agent/dsh-plans.git ~/.dsh/.agent-presets/dsh-plans

克隆到预设目录后,新会话即可选择该预设。

安全提示
安装插件会在你的机器上以你的权限运行第三方代码,可能读取文件、使用凭证、访问网络。工具审批不会对插件代码做沙箱隔离;收录列表不等于安全审查,安装前请审阅源码,陌生插件请在无密钥的环境试用。
