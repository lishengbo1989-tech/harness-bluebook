PART 02 · CH. 10

文件读写与代码编辑

read / write / edit / glob / grep:安全地查看、修改与检索文件,让每一次改动都可控、可复核。

#文件工具集

文件操作由五个工具分工完成,覆盖查看、写入、搜索三条链路:

  • read 按行号读取文件,支持 offset / limit 分段读大文件。
  • write 创建新文件,或整体替换文件内容。
  • edit 精确替换文件中的一段文本,适合小改动。
  • glob 按路径模式列出文件,如 **/*.md。
  • grep 按 ripgrep 正则搜索文件内容,返回命中行与行号。

#编辑的正确姿势

核心习惯只有一条:先读后改,小步提交。文件观察策略默认要求在修改前先读文件;改动要小,一次只解决一个问题,便于复核与回退。edit 的 old_string 必须唯一匹配——匹配到多处时,要么提供更长的上下文,要么显式使用 replace_all。

#搜索与定位

不知道文件在哪、或想找某段逻辑时,先搜索再阅读:用 glob 缩小文件范围,用 grep 定位具体行,再用 read 读取上下文。grep 使用 ripgrep 语法,支持正则与排除模式,效率远高于人肉翻文件。

# glob:找出所有 Markdown 文档
**/*.md

# grep:定位 TODO 与 FIXME 标记
TODO|FIXME

#一个完整例子

以「改一行配置」为例,标准流程是读 → 改 → 确认:

  1. 读。read 配置文件,确认当前值与上下文。
  2. 改。edit 精确替换目标行,old_string 取足够长的唯一片段。
  3. 确认。再 read 一遍改动区域,核对结果符合预期。

#注意

文件按 UTF-8 处理;超大文件用 offset / limit 分段读取,避免一次性加载过多内容。write 是整体覆盖,写之前务必先读、确认你理解文件全貌。

别覆盖你没读过的文件
write 不会问你要不要合并——它会直接替换全部内容。改动之前先 read;拿不准就小步 edit,而不是整文件重写。
