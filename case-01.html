审计一个仓库:依赖、安全与遗留问题

CODEBASHREVIEW

接手陌生仓库,先摸清依赖与风险,做一次只读审计,快速产出带出处的整改清单。

#场景与目标

接手一个停更近一年的仓库,需要快速回答三个问题:依赖有哪些、哪些已过时、有没有高危项与遗留问题(如弃用 API、TODO 标记)。目标是全程只读,产出一份按优先级排序的审计报告。

#用到的能力

  • 文件工具:用 read / glob / grep 定位清单文件与遗留标记,只读优先。
  • bash:执行版本与安全查询命令,检查 exit code 标记。
  • 后台任务:耗时查询用 run_in_background 启动,再用 job_output 收集。
  • 权限意识:默认 workspace-write 已够用;越界与危险操作会触发审批。

#操作过程

  1. 盘点结构。用 glob 找到 package.json 与锁文件,read 读取依赖清单与脚本字段。
  2. 查过时项。用 bash 运行 npm outdated 与 npm audit,记录输出与退出码。
  3. 扫遗留问题。用 grep 搜索 TODO、FIXME 与已弃用 API 的调用点,记录行号。
  4. 汇总成稿。按「高 / 中 / 低」排序,每条结论附文件与命令出处,输出整改清单。
审计这个仓库,输出四段式报告:
1. 结构概览:主要包与模块
2. 依赖健康度:过时项、高危项(附 npm audit 输出)
3. 遗留问题:TODO / FIXME / 弃用 API 调用点
4. 整改优先级:高 / 中 / 低,每条附出处

#实际效果

约 25 分钟完成审计:找出 3 个高危依赖、12 个过时包、4 处遗留 TODO;报告带出处与优先级,确认后分批升级。

#验收标准

  • 报告含优先级排序,每条结论可追溯到具体文件或命令输出。
  • 审计期间零文件改动。
  • 整改清单可直接交给开发分批执行。

#可复用资产

「仓库审计提示词模板」:输入仓库路径,输出结构概览、依赖健康度、遗留问题、整改优先级四段式报告;改改路径即可复用到任何仓库。

安全边界
审计以只读为主;不要在人工确认前运行 npm install / npm update 等会改动仓库的命令。破坏性操作会触发审批,审批无应答时按 fail-closed 默认拒绝。
