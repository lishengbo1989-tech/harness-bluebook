## 1. 项目事实(推广必须基于事实,禁止夸大)

- 项目:DSH 实战蓝皮书——DeepSeek Harness 的中文社区实践指南(静态文档站)。
- 站点:https://lishengbo1989-tech.github.io/harness-bluebook/ (GitHub Pages)
- 内容:19 个页面;蓝皮书 4 篇 24 章规划,其中 **7 章已有完整正文**(第 2/4/5/6/9/10/18 章:安装启动、配置模型、第一个任务、沙箱与权限、bash、文件读写、一切皆插件);**6 个完整社区案例**(仓库审计、文件整理、子代理并行调研、长期目标、文档重写、每周巡检);另有首页/阅读指南/案例集/帮你解决等栏目。
- 主题产品:DeepSeek Harness(`dsh`),DeepSeek AI 开源的 agent harness,`npx @deepseek-ai/dsh web` 一键启动,Web UI 默认 http://127.0.0.1:3080;「一切皆插件」架构(Cordis);能力:子代理、工作流编排、长期目标、Skills、沙箱权限、后台任务。官方仓库 https://github.com/deepseek-ai/DeepSeek-Harness
- 定位:社区共创、开源、以真实任务为主线;「从 0 到 1 先用起来,从 1 到 100 沉淀工作系统」。
- 状态:开发者预览阶段;社区项目,与官方无隶属关系。
- 传播钩子(可强调):「社区蓝皮书,章节欢迎认领写作」「6 个可复现案例」「阅读指南按角色给路线」。

## 2. 基调与红线

- 基调:实用、真诚、工程师向;软推广,不喊口号、不用「震惊体」、不贬低竞品。
- 红线:不虚构功能/数据/用户量;不承诺效果;如实说明是社区项目、开发者预览阶段。
- 文风:中文稿口语化但专业;英文稿简洁直接。
- 每篇必须有 CTA:引导访问网站、或参与共创(GitHub)。

## 3. 交付物(写入 `/Users/libobo/Documents/deepseek/Harness community/harness-bluebook/promo/` 目录)

每平台一个 markdown 文件,包含:
1. 标题方案:2–3 个备选(标注推荐)
2. 正文全文(可直接复制发布;中文 800–1500 字,英文 200–400 词)
3. 配图建议(引用站点截图/og 图;写明建议截哪一页)
4. 话题标签/关键词(中文平台给标签,Reddit 给 subreddit, HN 给标题风格建议)
5. 评论区互动建议(自答 1–2 条、引导讨论的提问)

### 3.1 中文平台(掘金 / 知乎 / 公众号 / CSDN)
- 掘金:偏技术实践,开头给「背景+痛点」,正文带 2–3 个代码块/截图位,结尾 CTA。标题示例方向:「开源实战蓝皮书:从 0 到 100 把 DeepSeek Harness 用起来」
- 知乎:问题式或经验式,开头 100 字内给结论;语气「亲测/整理」;可带「如何评价/如何入门」句式。
- 公众号:标题可带情绪钩子但克制;开头 200 字摘要;适当分段、小标题;文末放二维码占位与「在看/分享」引导。
- CSDN:结构清晰、步骤感强;标题带「实战/教程/收藏」;结尾引导收藏。

### 3.2 英文平台(Reddit / Hacker News)
- Reddit:每帖 150–300 词,第一人称经验帖口吻;给 2 个版本:r/artificial 通用版、r/selfhosted 或 r/LocalLLaMA 技术版;附 subreddit 发帖规范提醒(自荐帖需先参与社区、遵守 10% 规则)。
- Hacker News:标题 80 字符内,陈述事实式(如 "Show HN: An open-source Chinese guide for DeepSeek Harness");正文 200–400 词,第一人称,讲清「为什么做、有什么、给谁用」;附评论首条引导。

- 每个文件含全部 5 个要素;事实与第 1 节一致;无夸大;中文稿无错别字;英文稿语法通顺。
- 汇报:创建的文件清单、每篇字数、自查结果。
