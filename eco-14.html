生态案例:游戏与 3D

GAMING3DBRIDGE

在会话里检查 Godot 场景、求值 GDScript,也驱动 Blender 的建模、渲染与导出。

#场景与目标

游戏开发者与 3D 美术常常要在编辑器里反复手动操作。目标是让 DSH 直接连接 Godot 引擎运行时与 Blender 生产管线,把检查场景、调试脚本、建模重建这类工作变成可对话、可复用的操作。

#用到的能力

  • 引擎运行时桥:godot-bridge 提供 8 个工具连接 DSH 与 Godot,可替代 godot-mcp。
  • 场景操作:检查场景与 UI、求值 GDScript、模拟输入、截图。
  • 3D 生产:blender 提供 30 个建模/重建技能与 13 个运行时工具。
  • 生产流程:覆盖参考拟合、渲染、校验、动画与导出。

#怎么做到的

godot-bridge 在 DSH 与 Godot 运行时之间建立通道,8 个工具覆盖场景/UI 检查、GDScript 求值、输入模拟与截图,调试不必切出编辑器;blender 把建模与重建拆成 30 个技能,13 个运行时工具处理参考拟合、渲染、校验、动画与导出,沉淀为可复用的 3D 生产管线。

#实际效果

游戏调试与 3D 资产操作可以在对话里直接驱动,常见操作被封装成技能,重复的建模与重建流程可复用;渲染与导出走固定工具,减少了手工点击与来回切换。

#出处与上手

  • github.com/Smalldy/godot-bridge — DSH↔Godot 运行时桥
  • github.com/CheshireJCat/blender — Blender 3D 生产插件
dsh plugin --profile web add godot-bridge
dsh plugin --profile web add blender

具体加载方式与依赖以各仓库 README 为准。
