SSH 远程运维:dsh-ssh-ops

SSHOPSTERMINAL

在 DSH 的 Web UI 里直接驱动远程服务器,右侧保留一块交互式终端,AI 干活、你盯屏。

#场景与目标

传统远程运维要在终端和 AI 会话之间来回切换:开 SSH、敲命令、把输出复制回来。dsh-ssh-ops 的目标是让这一切发生在 DSH Web UI 里——主会话直接驱动已连接的服务器,右侧保留交互式 xterm.js 终端,适合「AI 执行 + 人工盯屏」的运维场景。

#用到的能力

  • 插件机制:通过 Cordis 插件把 ssh_* 工具注册进会话,一个插件补齐远程操作能力。
  • 工具回路:主会话用 ssh_exec / ssh_read / ssh_write 执行命令并读写输出,可持续跟进。
  • Web UI 集成:连接状态与交互式 xterm.js 终端保留在右侧,人与 AI 共用同一台服务器。

#怎么做到的

插件封装了 SSH 连接的完整生命周期:ssh_connect 建立连接,ssh_exec 执行命令,ssh_read / ssh_write 做流式读写,ssh_disconnect 断开。连接后主会话把命令发给远程进程,输出回到会话供 AI 判断下一步;右侧终端同时可见,交互过程不离开 Web UI。

#实际效果

「开终端 → 敲命令 → 复制回会话」的往返,变成主会话内的一次工具调用;连接管理、命令执行、输出读取都在 Web UI 里完成,远程运维过程可对话、可留痕。

#出处与上手

社区仓库:github.com/caoyiwei850/dsh-ssh-ops

安装插件:

dsh plugin --profile web add dsh-ssh-ops

首次使用前,请阅读仓库 README,了解连接配置与主机权限要求。

安全提示
安装插件会在你的机器上以你的权限运行第三方代码,可能读取文件、使用凭证、访问网络。工具审批不会对插件代码做沙箱隔离;收录列表不等于安全审查,安装前请审阅源码,陌生插件请在无密钥的环境试用。
