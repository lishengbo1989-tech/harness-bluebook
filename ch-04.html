PART 01 · CH. 04

配置模型提供方

本章解决「让 dsh 开口说话」的问题:在 Web UI 里填入模型提供方信息,保存即生效,并知道如何安全地保管密钥。

#设置 → 模型

打开 Web UI,进入「设置 → 模型」,填入你的 DeepSeek API 密钥。保存后模型路由立即生效——无需重启 Web UI 或 dsh 进程,直接回到会话窗口就能开始对话。这也是 Web UI 上手最快的路径:只填一个密钥,其他保持默认即可。

#其他提供方与自定义端点

除了 DeepSeek 官方 API,dsh 还支持其他提供方,以及 OpenAI 兼容的自定义端点——比如私有化部署的兼容服务。各家提供方的配置项与端点格式不同,接入步骤参见官方文档 docs/user/guide/providers;拿不准时,以官方仓库为准。

#密钥安全

  • 不要提交到仓库。API 密钥不要写进代码、配置或任何会进入版本控制的文件。
  • 不要粘贴到公开渠道。不要发到群聊、公开 Issue、截图或演示里。
  • 泄露即轮换。怀疑密钥泄露时,尽快到提供方控制台吊销并换新。
保存即生效
密钥保存后模型路由立即可用,无需重启。若后续行为异常,先检查密钥是否有效、提供方是否可用,再考虑其他排查方向。

#验证配置

配置是否生效,发一个简单任务就能验证:

  1. 选中工作区。在 Web UI 添加并选中一个工作区——选中工作区前,会话输入框是不可用的(工作区细节见第 5 章)。
  2. 发送一个简单任务。例如让它总结当前工作区:
Summarize this repository and identify its main packages.

模型能正常回复,说明密钥与路由配置成功;若提示鉴权失败,检查密钥是否完整、是否选对了提供方。

#下一步

模型已就绪,下一步进入第 5 章 第一个任务,让 agent 跑通第一次真实的文件读取与总结,并理解它的完整工作回路。
