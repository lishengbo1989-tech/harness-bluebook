PART 02 · CH. 09

用 bash 执行命令与脚本

让 agent 在你的工作区里真正"动手":探测环境、执行命令、解读输出,再把重复操作脚本化。

#先探测环境

让 agent 动手之前,先确认它站在哪里、手里有什么工具。习惯上先用 pwd 确认当前目录,用 ls 看看工作区里有什么文件,再按需检查工具版本,比如 node -v。命令默认在会话工作区的沙箱内运行,输出会实时出现在会话里。

pwd
ls
node -v

#读输出与退出码

每次命令执行的结果都带有 [exit code: N] 标记:0 表示成功,非零表示失败。看到失败不要盲目重试——先读输出、调查原因,再决定下一步。输出很长时界面会截断显示,完整内容会保存到文件,必要时再取一次。

  • 先看退出码,再决定是继续还是排查。
  • 失败要调查:读错误信息、确认路径与参数,再重试。
  • 长输出不截断判断:以保存的完整输出为准。

#后台任务

耗时的命令不必堵住主线工作。用 run_in_background 启动长任务,会立刻返回一个 job id;之后用 job_output 收集输出,用 job_kill 停止不再需要的任务。

  1. 后台启动。长命令以 run_in_background 方式运行,拿到 job id。
  2. 继续主线。不必轮询等待,任务结束时会收到通知。
  3. 收集结果。用 job_output 读取输出,再决定后续动作。
  4. 及时停止。不再需要的任务用 job_kill 收掉,别让它空转。

#脚本化常见操作

重复性的机械操作,与其一条条执行,不如写成脚本一次跑完。例如把一批 *.tmp 文件按模式重命名为 *.bak:

for f in *.tmp; do
  mv "$f" "${f%.tmp}.bak"
done

脚本化之前,先在小范围干跑一遍,确认模式匹配正确,再应用到全部文件。

#安全注意

命令在沙箱内运行,受当前权限策略约束:默认策略是 workspace-write,只可读写会话工作区;删除、覆盖、越界访问等危险操作会触发审批,升级到 danger-full-access 需要说明理由。审批策略可能 fail-closed——没有应答时,请求会被拒绝。

先想清楚再执行
删除与覆盖不可逆。涉及 rm、mv、外部网络请求的命令,先在脑内过一遍影响范围;把握不准时,把任务拆小,交给审批流程把关。
