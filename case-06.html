CASE · BASH

每周自动化巡检:依赖与安全告警汇总

BASHWORKFLOWAUTOMATION

每周手动检查依赖、安全公告与构建状态太麻烦。用 workflow 脚本把它变成一条命令的自动巡检。

#场景与目标

每周都要手动确认「依赖有没有可升级、有没有新安全公告、构建还绿不绿」。目标是脚本化:一条命令跑完全部检查,自动产出带结论的巡检周报。

#用到的能力

  • 工作流编排:workflow 用 JavaScript 脚本编排多路子检查,phase(title) 标记阶段进度。
  • 子代理:每路检查一个 agent,可带 schema 校验结构化结果。
  • bash:依赖查询、构建命令与退出码检查。
  • 后台任务:整个巡检可 run_in_background 启动,完成后统一收集。

#操作过程

  1. 写脚本。编排四步:依赖版本检查、安全公告检查、构建状态检查、汇总报告。
  2. 分阶段执行。用 phase("依赖检查") 等标记进度;每路一个独立 agent 并行跑。
  3. 后台运行。整条巡检作为后台任务启动,不占用主会话。
  4. 汇总出报。合并各路输出,生成含结论的巡检周报。
phase("依赖检查");  // agent 跑 npm outdated
phase("安全公告");  // agent 查 npm audit 与公告
phase("构建状态");  // agent 跑构建并读退出码
phase("汇总报告");  // 合并三路结果,生成周报

#实际效果

每周在 Harness 里运行一次巡检脚本,自动产出周报:本周 5 个可升级依赖、1 条高危公告、构建通过;人工只需看结论决定是否升级。

#验收标准

  • 报告覆盖全部检查项,每项都有结论。
  • 任一路失败会在报告中标出,不静默跳过。
  • 脚本可重复运行,结果稳定。

#可复用资产

「巡检 workflow 脚本模板」:含阶段定义(依赖 / 安全 / 构建 / 汇总)、每路 agent 的 prompt 与 schema 校验、结果合并逻辑;改改仓库路径即可复用。

安全边界
自动巡检以只读为主;升级依赖、改动仓库仍是需要审批与人工确认的动作。安全结论请以官方公告渠道为准。
