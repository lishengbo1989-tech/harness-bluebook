批量整理下载目录:重命名、归档与去重

FILESSCRIPTS

300+ 文件一团乱?按类型与日期规则批量归档、重命名、去重,先干跑、后确认、再执行。

#场景与目标

下载目录积压 300+ 文件:截图、安装包、文档、压缩包混在一起,命名混乱、重复文件多。目标是整理成清晰结构,规则可复用,而且绝不能误删任何文件。

#用到的能力

  • 文件工具:用 glob 按扩展名枚举文件,read 查看干跑计划。
  • bash:批量脚本执行移动 / 重命名 / 去重,并检查 exit code。
  • 编辑工具:用 write / edit 生成并修正整理脚本。
  • 审批感知:批量删除属破坏性操作,人工确认后才会真正执行。

#操作过程

  1. 枚举清单。用 glob 收集全部文件,按类型统计数量与体积。
  2. 设计规则。按「类型 / 年-月」归档,统一命名规范,定义按哈希去重。
  3. 干跑计划。生成「将移动 X → Y、将删除重复项 Z」的预览清单,不执行任何变更。
  4. 人工确认。把清单交给用户核对,批准后再进入执行阶段。
  5. 执行复核。bash 运行脚本,读输出核对数量,与预期清单逐项比对。
# 干跑计划示例(仅预览,不执行)
移动 downloads/screenshot-2024-01-01.png → downloads/图片/2024-01/
删除重复项 downloads/副本 (2).zip(与 副本.zip 哈希相同)
统计:342 个文件 → 移动 296、删除 8、保留 38

#实际效果

300+ 文件整理为「类型 / 日期」归档结构,删除 8 个重复文件,零误删;规则沉淀为 skill,下次一键执行。

#验收标准

  • 执行前清单与执行后目录结构一一对应。
  • 误删为 0,删除项均有哈希佐证。
  • 重命名与归档结果符合既定规则。

#可复用资产

「干跑 - 确认 - 执行」模板:任何批量变更都先产出可读计划,人工确认后才落盘;可沉淀为 skill 反复使用。

安全边界
批量删除与移动前务必先看干跑清单。默认 workspace-write 只覆盖会话工作区,越界路径操作会触发审批;审批无应答时按 fail-closed 默认拒绝。
