PART 01 · CH. 05

第一个任务:让 agent 跑通一次真实操作

本章解决「第一次真正干活」的问题:选好工作区、发出第一个任务,并理解 agent 读文件、思考、调工具、检查的完整回路。

#先选择工作区

dsh 进程把启动时的调用目录作为默认的文件系统位置;但新 Web UI 在添加工作区前不选中任何工作区——而选中工作区之前,会话输入框不可用。所以开工第一步永远是:在 Web UI 里添加并选中一个工作区。agent 之后就在这个边界内读写文件、运行命令。

#发送第一个任务

官方文档给出的示例任务,非常适合当第一个「验收对象」:

Summarize this repository and identify its main packages.

把它粘贴进会话输入框发送。这个任务要求 agent 真正去读仓库,而不是凭印象回答——从它的回复里,你能判断工具链路是否已经打通。

#理解 agent 的回路

agent 不是一次性回答,而是在一个循环里工作:读文件 → 思考 → 调用工具 → 检查结果,必要时重复。它具备的能力包括:

  • 读取与编辑工作区文件;
  • 运行命令并解读输出;
  • 委派子任务、维护自己的执行计划;
  • 当操作在当前权限策略下需要审批时,停下来先询问你。

理解这个回路,你就明白为什么「等它自己完成」比「催促它」更有效:每一步都需要读文件、调工具和检查,这是一个多步骤过程。

#任务验收

  1. 核对事实。回复里列出的包名,是否与仓库中真实的依赖清单一致?
  2. 要求出处。让它指出依据的文件路径,而不是只给结论。
  3. 预先定标准。比如「列出至少三个主要包并说明用途」,再对照判断是否达成。
第一次别贪多
第一个任务选小一点、可验收的,先把回路跑通;跑通一次,你就得到了一份可复用的任务模板。

#下一步

任务能跑通之后,下一个问题就是边界:第 6 章 沙箱与权限解释 agent 默认能在哪里读写、什么操作会触发审批、升级权限意味着什么。
