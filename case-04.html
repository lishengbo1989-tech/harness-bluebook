长期目标:持续改进一个开源小项目

GOALSPLAN

「改进项目」太空泛?把它拆成多轮可验收的目标,每轮验收后自动续跑,全程留痕可回溯。

#场景与目标

开源小项目想持续改进,但「改进」太宽泛,往往做一轮就停。目标是拆成多轮自动推进的过程:分析 → 设计 → 实现 → 测试 → 文档,每轮都有产出与留痕,而不是一次性的冲动改造。

#用到的能力

  • 长期目标:create_goal 建立目标,update_goal 记录进度,get_goal 查询状态;支持多轮自动续跑。
  • 计划模式:先规划再动手,exit_plan_mode 提交计划供确认。
  • 文件工具:用 read / write / edit 落地代码与测试,先读后改。
  • bash:运行测试与构建,检查退出码,失败先调查再继续。

#操作过程

  1. 拆解目标。create_goal 把大目标拆成「分析 → 设计 → 实现 → 测试 → 文档」多轮。
  2. 计划先行。进入计划模式,每轮先提交计划,确认后再执行。
  3. 逐轮推进。一轮一个可验收产出;验收通过后用 update_goal 记录进度并续跑下一轮。
  4. 留痕回溯。用 get_goal 查看当前状态;每轮产出写入仓库,便于回看。

#实际效果

连续多轮完成 3 个 feature,配套测试与文档同步更新;每轮验收通过自动进入下一轮,全程留痕可回溯。

#验收标准

  • 每一轮都有具体产出(代码 / 测试 / 文档)与记录。
  • get_goal 可随时查到目标状态与进度。
  • 同一阻塞持续多轮才标记 blocked,不轻易放弃。

#可复用资产

「长期目标拆解模板」:大目标 → 可验收轮次(分析 / 设计 / 实现 / 测试 / 文档)→ 每轮验收标准 → 续跑条件;适配任何想持续推进的项目。

安全边界
自动续跑不等于无人值守;破坏性变更仍会触发审批。目标范围过大时及时用 update_goal 收敛,避免无限续跑。
