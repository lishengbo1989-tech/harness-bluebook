PART 01 · CH. 02

下载、安装与启动

本章解决从零开始的问题:检查环境、启动 dsh 的 Web UI,并知道出问题时去哪里排查,为第 4 章配置模型做好准备。

#环境要求

DeepSeek Harness(简称 dsh)是 DeepSeek AI 开源的 Agent 框架,架构上「一切皆插件」、由 Cordis 驱动。安装运行它只需要一个前提:Node.js 运行时。

  • Node.js。dsh 的启动与运行都基于 Node.js,先确保本机有可用的 Node.js 环境。
  • 按需准备 git 与 pnpm。走 npx 方式不需要它们;从源码构建才需要(见下文)。

Node.js 的具体版本要求会随版本演进,拿不准时以官方仓库的说明为准。

#通过 npm 启动

最省事的启动方式是 npx——一条命令拉取并运行 dsh,启动 Web UI:

npx @deepseek-ai/dsh web

Web UI 的默认地址是 http://127.0.0.1:3080;首次运行会在终端打印访问地址,把它复制到浏览器打开即可。完整走一遍:

  1. 确认 Node.js。在终端运行 node -v,能输出版本号即可。
  2. 启动。运行 npx @deepseek-ai/dsh web,等待启动完成。
  3. 打开地址。浏览器访问 http://127.0.0.1:3080,看到 Web UI 即启动成功。

#从源码运行

想跟紧开发进度、阅读源码或参与贡献,可以从源码构建,四个步骤:

git clone https://github.com/deepseek-ai/deepseek-harness.git
pnpm install
pnpm run build
pnpm dsh web

克隆官方仓库、安装依赖、构建,最后用 pnpm dsh web 启动,访问地址同样是默认的 http://127.0.0.1:3080。

#常见问题

  • 端口被占用。默认地址 http://127.0.0.1:3080 打不开,通常是该端口已被其他进程占用;先排查占用进程,端口相关配置参见官方文档。
  • npx 缓存异常。拉取到旧版本或行为与文档不一致时,清理 npx 缓存后重试,具体方法参见官方文档。
  • 版本差异。当前处于开发者预览阶段,会有破坏性变更,升级后行为可能变化,以官方发布说明为准。
拿不准就看官方
本文只覆盖安装主路径,Node.js 版本、端口、缓存等细节在不同环境下可能不同;遇到不一致,优先查阅 DeepSeek Harness 官方仓库。

#下一步

Web UI 已经跑起来,但它还不能干活——dsh 需要先接上模型提供方。建议先快速浏览第 3 章 Web UI 漫游熟悉界面,再进入第 4 章 配置模型提供方填入 API 密钥。
